# Review App Support Design

## Goal

Add Control Plane Flow review-app support so maintainers can create temporary PR environments with `+review-app-deploy`, update them on PR pushes, delete them on command or PR close, and clean up stale apps nightly.

## Architecture

Use the standard Control Plane Flow model from `controlplaneflow.com`: keep the existing persistent Control Plane app, add a review-app prefix entry to `.controlplane/controlplane.yml`, and add the generated `cpflow-*` GitHub Actions wrappers. The wrapper logic stays upstream in `shakacode/control-plane-flow`; this repo only pins the generated callers to the installed `cpflow` release.

## Configuration

The review app entry will be named `react-server-components-demo-review` and set `match_if_app_name_starts_with: true`, allowing PR apps such as `react-server-components-demo-review-123`. It will reuse the existing templates, staging org, and `rails db:migrate` release phase. Because the app points at an external database secret rather than a per-review-app Postgres template, deletion will not run `rails db:drop`.

## Workflows

Generated workflows will support PR help comments, `+review-app-deploy`, automatic redeploys after the first deploy request, `+review-app-delete`, PR-close cleanup, and scheduled stale-app cleanup. Staging and production wrappers generated by `cpflow` may also be present, but review apps are the primary supported behavior in this change.

## Documentation

Update `.controlplane/README.md` with the review-app commands, required GitHub secret `CPLN_TOKEN_STAGING`, optional variables for private Docker builds, and the Control Plane secret values the review apps reuse.

## Verification

Run `ruby -S cpflow github-flow-readiness` before generation, then run the generated `bin/test-cpflow-github-flow` after the files exist. Inspect the generated workflow YAML and final git diff before reporting completion.
